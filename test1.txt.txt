📘 SOP: Application Decommissioning – PCF / Jenkins / UCD / DevOps Tools


---

1. Purpose

This SOP describes the end-to-end process to safely decommission an application across all DevOps platforms, including PCF, Jenkins, CloudBees CD (UCD), Sonar, Infosec, and source code repositories.

This document ensures:

No orphaned resources remain

Production risk is minimized

Compliance and audit requirements are met

Any engineer can execute the steps without prior context



---

2. Scope

This SOP applies to:

Single-module applications

Multi-module applications

Microservices

Batch applications deployed on PCF



---

3. Responsibility Matrix

Role	Responsibility

App Owner	Provides approval for decommission
Sphere / Dev Lead	Confirms app/module to be decommissioned
DSE DevOps Team	Technical guidance & validation
PCF Ops Team	PCF app, job, task & route removal
Enterprise DevOps	UCD & CloudBees CD cleanup
Infosec Team	Security system cleanup



---

4. Preconditions (Must Be Completed Before Starting)

✔ App owner approval email available

✔ Confirmation of environments (Dev / Prod)

✔ Confirmation if app is single-module or multi-module

✔ Change Request raised for Production (if applicable)



---

5. Step-by-Step Decommissioning Procedure


---

Step 1: Remove PCF Application / Job / Task

Applicability

All PCF-deployed applications

Mandatory for both Dev and Prod


Actions

1. Identify:

App name

Job name (for batch apps)

Task name (for batch apps)

Environments (Dev & Prod)



2. Send email to pcf.appops@syf.com with:

App name

Job/task details

Environment details

App owner approval attached



3. After confirmation:

Verify the app is removed from PCF

Verify routes are unbound and removed

Check Routes section (left-hand panel) in PCF UI




Validation

✔ App not visible in PCF
✔ Job/Task removed (if batch app)
✔ Route unbound and deleted


---

Step 2: Decommission PCF Route / GTM


---

DEV Environment

1. Send email to pcf.appops@syf.com with:

App name

Foundation details

Route type (PCF route)




✔ No change ticket required for Dev


---

PROD Environment

1. Raise Change Request with:

App owner approval attached

GTM / PCF route removal details



2. Reference sample change:

CHG0861248



3. After ticket approval:

Notify PCF Ops team via email




Validation

✔ Route removed from PCF
✔ GTM entry decommissioned


---

Step 3: Jenkins Job Decommission


---

Single Module Application

1. Move Jenkins job to ARCHIVE location:



Paths

Dev: DSE-MICROSERVICES-DEV > ARCHIVE > TO_BE_DELETED

Prod: DSE-MICROSERVICES-PROD > ARCHIVE > TO_BE_DELETED


✔ Job is no longer active


---

Multi-Module Application

1. Open Jenkins job


2. Click Configure


3. Remove decommissioned module from Deployable Modules


4. Save configuration



✔ Remaining modules still deploy correctly


---

Step 4: Remove UDeploy (UCD) Configuration


---

Actions

1. Raise RITM to DevOpsSupport@syf.com


2. Provide:

App name

Component(s)

Processes (Blue/Green/Rollback)

Environment(s)

Justification

App owner approval attached




Reference RITMs

RITM2568465

RITM2576827


Validation

✔ Components removed
✔ App processes removed
✔ No environment bindings remain


---

Step 5: Infosec Application Removal


---

Actions

1. Raise RITM to Infosec App Team using Infosec portal


2. Provide one of the following:

Change Request number (PCF decommission), OR

Jira story number (created by app team)




Reference RITM

RITM2577273


Validation

✔ App removed from Infosec systems


---

Step 6: SonarQube Application Removal


---

Actions

1. Remove project from SonarQube


2. Ensure no scheduled scans remain



Validation

✔ Sonar project no longer exists
✔ No pipelines reference Sonar project


---

Step 7: CloudBees CD Self-Service Decommission


---

Actions

1. Raise RITM to DevOpsSupport@syf.com


2. Include:

Microservice name

Justification

App owner approval




Reference RITMs

RITM2568465

RITM2576827


Validation

✔ Self-service deployment disabled
✔ App not visible in CloudBees CD


---

Step 8: Source Code Repository Cleanup


---

Single Module Repository

1. Open repository


2. Go to Repository Settings


3. Scroll to Repository Details


4. Click Archive



⚠ Delete repository only after written app owner approval

✔ Repo archived or deleted


---

Multi-Module Repository

1. Remove code related to decommissioned module


2. Ensure:

Build files updated

CI pipelines updated

No references to removed module




✔ Remaining modules build successfully


---

✅ FINAL DECOMMISSION CHECKLIST

Use this checklist before closing the ticket.


---

PCF

⬜ App removed (Dev)

⬜ App removed (Prod)

⬜ Job removed (Batch apps)

⬜ Task removed (Batch apps)

⬜ Routes removed



---

Routing / GTM

⬜ Dev route removed

⬜ Prod GTM removed

⬜ Change Request approved



---

Jenkins

⬜ Job archived (single module)

⬜ Module removed from job (multi-module)



---

UCD / CloudBees

⬜ Components removed

⬜ App processes removed

⬜ Self-service deployment disabled



---

Security & Quality

⬜ Infosec entry removed

⬜ Sonar project removed



---

Source Code

⬜ Repo archived or deleted (single module)

⬜ Module removed from repo (multi-module)

⬜ Pipelines updated



---

Final Validation

⬜ No active pipelines

⬜ No production endpoints

⬜ All approvals attached

⬜ Tickets updated & closed
